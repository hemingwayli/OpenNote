# 数据处理与隐私

OpenNote 的文档、OCR、摘录、批注和笔记处理以本地资料库为边界。导入时复制原文件供应用管理，不修改书籍原件。本文说明现有数据行为及公开反馈时的注意事项，不代替对运行环境或第三方组件的独立安全审计。

## 资料位置

Windows 默认资料目录为 `%LOCALAPPDATA%\OpenNote`，程序默认安装于 `%LOCALAPPDATA%\Programs\OpenNote`。开发、候选和自检使用独立资料库；`--data-dir=<绝对路径>` 可以指定资料位置。

资料库包含原文、笔记、个人思考、截图、OCR 文字层、阅读位置和附件。完整备份会包含这些内容，不是只有设置或空白数据库。请把资料目录与备份视为私人文件，不放入公开仓库或公共分享目录。

## 离线与网络边界

PDF 和 OCR 使用随包分发的本地引擎与模型。EPUB 使用系统 WebView2 和本地阅读资源；正文通过仅绑定 `127.0.0.1` 的临时端口提供给本机 WebView。这个本地连接不表示云同步。

书籍脚本、外网资源、音视频及 DRM 授权不属于支持范围。WebView2 安装、开发依赖准备和外部工具可能需要网络，它们的系统行为不由本软件的离线处理合同替代。不要将“资料在本地处理”扩大为整个操作系统和所有组件永不联网的保证。

## 日志、截图与问题反馈

日志和错误可能包含文件路径、文档名、资源标识或环境信息。公开反馈前检查并隐藏系统用户名、私人目录、正文、文件指纹、批注、个人思考、账号及密钥。使用自产最小文档复现；不要上传原书或完整资料库。

界面图可能包含项目名称、书籍封面和笔记。README 示例使用自产演示资料；从个人资料库截图前应先更换为演示项目，并检查画面及文件元数据。

## 贡献与分发

个人交流偏好、其他项目的约定和本机工具配置保存在工具的用户配置目录；项目专用的私有规则、审查报告与原始证据保存在被忽略的 `.local/`，不要复制到公开协作文档。

仓库可提供经审查的可移植 IDE 配置模板，例如 `.vscode/settings.example.json`。实际 SDK 路径、服务凭据和个人配置仅在本地填写，不回写到公开模板。

`.local/`、数据文件、备份、构建产物、实际 IDE/MCP 配置及 SDK 路径不进入源码分发。二进制素材须由 `packaging/source-assets.json` 声明来源并匹配固定字节。测试采用自产文档或明确声明来源的公共样本，公共样本不表示私人原书可以分发。

恢复、迁移、安装生命周期测试使用独立资料库；执行前保留备份。删除程序与删除资料是不同操作，不能把卸载当作隐私擦除方式。

普通问题使用仓库 Issues，安全问题按 [安全策略](../SECURITY.md)报告。不要公开他人的私人信息。
